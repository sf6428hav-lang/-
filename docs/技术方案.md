# 技术方案

## 1. 概述

本文档描述短剧剧本生成工具的技术架构、技术选型、项目结构和部署方案。

**核心链路**：用户粘贴分享链接 → 自动解析视频直链 → 下载视频 → Gemini 3.1 Pro 多模态分析 → 输出《麻将声》格式剧本

---

## 2. 技术选型

### 2.1 后端：Python FastAPI

| 选型 | 理由 |
|------|------|
| **FastAPI** | 异步原生，天然支持 LLM 调用的长时间等待；自动生成 API 文档；自带静态文件托管和 CORS 支持 |
| **Python 3.11+** | google-generativeai、python-docx 等核心依赖均为 Python 生态独占；3.11+ 的 TaskGroup 适合并发下载链路 |
| **uvicorn** | FastAPI 官方推荐 ASGI 服务器，生产级表现 |

核心依赖：

| 包名 | 用途 |
|------|------|
| `fastapi` + `uvicorn[standard]` | Web 框架和服务器 |
| `google-generativeai` | 调用 Gemini 3.1 Pro 多模态 API |
| `httpx` | 异步下载视频文件、请求外部 API |
| `beautifulsoup4` + `lxml` | 解析红果 H5 分享页 |
| `python-docx` | 生成 docx 格式剧本 |
| `aiosqlite` | 异步 SQLite 操作 |

### 2.2 前端：纯 HTML + CSS + JavaScript

不引入任何前端框架或构建工具，原因：

- 界面为单页布局，交互复杂度低（输入框、链接队列、进度条、剧本正文、历史列表）
- 2 人自用，无需 SEO、SSR、路由等现代框架能力
- 避免构建工具链和 node_modules 的维护负担

FastAPI 通过 `StaticFiles` 直接托管前端文件，开发时直接编辑刷新即可。

### 2.3 数据库：SQLite

- 2 人使用，零并发压力，SQLite 绰绰有余
- 零配置，不需要单独安装数据库服务
- 使用 `aiosqlite` 适配 FastAPI 异步风格
- 剧本原文以 .txt 文件存储，数据库中只存储元数据

### 2.4 外部服务

| 服务 | 接入方式 |
|------|----------|
| **Gemini 3.1 Pro** | 用户自备 API Key，调用 `google-generativeai` 的 `generate_content` 传视频 + 提示词 |
| **红果短剧** | 解析分享页 H5，从页面数据中提取 MP4 直链 |
| **抖音视频** | 通过 `yzfly/douyin-mcp-server` 或 `Douyin_TikTok_Download_API` 获取视频文件 |

## 4. API 设计

### 4.1 生成剧本

```
POST /api/generate
Content-Type: application/json

{
  "links": [
    "https://hongguo.page.link/xxx",
    "https://www.douyin.com/video/xxx"
  ]
}

→ 返回 SSE 流式响应，实时推送进度：
{
  "type": "progress",
  "index": 0,
  "status": "parsing" | "downloading" | "generating" | "done" | "failed",
  "message": "正在解析链接..."
}

→ 全部完成后推送：
{
  "type": "complete",
  "records": [
    { "id": "xxx", "title": "深宫恨 第1集", "status": "done" }
  ]
}
```

使用 SSE（Server-Sent Events）推送进度，避免轮询。

### 4.2 读取剧本

```
GET /api/scripts/{id}
→ 返回剧本元数据和正文内容
```

### 4.3 下载剧本

```
GET /api/scripts/{id}/download?format=docx|txt
→ 返回对应格式的文件下载
```

### 4.4 历史记录

```
GET /api/history?page=1&page_size=20
→ 返回历史记录列表（按时间倒序）
```

### 4.5 删除记录

```
DELETE /api/history/{id}
→ 删除对应记录及文件
```

### 4.6 设置管理

```
GET  /api/settings          → 获取当前设置（API Key 脱敏返回）
PUT  /api/settings          → 更新设置
```

## 5. 核心技术流程

### 5.1 生成剧本（单条链路）

```
粘贴链接 → 输入框确认 → 加入队列
  ↓
用户点击"开始生成"
  ↓
SSE 推送进度事件
  ↓
① 识别平台（红果/抖音/其他）
  ↓
② 解析链接获取视频直链
  ↓
③ 下载视频文件（临时存储）
  ↓
④ 调用 Gemini 3.1 Pro：
   视频文件 + 《麻将声》提示词模板 → 结构化剧本
  ↓
⑤ 保存剧本原文到 data/scripts/{id}.txt
  ↓
⑥ 记录元数据到 SQLite
  ↓
⑦ 清理临时视频文件
  ↓
SSE 推送完成事件
```

### 5.2 红果链接解析

```
分享链接 → 302 跳转到 H5 页面
  ↓
请求 H5 页面 → 提取 <script> 中的 __NEXT_DATA__ 或 SSR 数据
  ↓
解析 play_url → 得到 MP4 直链
  ↓
（已验证可通，无需加密处理）
```

### 5.3 抖音链接解析

```
分享链接 → 调用 yzfly/douyin-mcp-server
  ↓
返回视频下载地址
  ↓
异步下载视频文件
  ↓
（备选：Douyin_TikTok_Download_API）
```

### 5.4 Gemini 视频分析

```
async def generate_script(video_path: str, prompt: str) -> str:
    client = genai.Client(api_key=settings.gemini_api_key)

    # 小文件直接传，大文件走 File API
    if os.path.getsize(video_path) < 20 * 1024 * 1024:
        video_part = client.upload_file(path=video_path)
    else:
        video_part = client.files.upload(file=video_path)

    response = client.models.generate_content(
        model="gemini-3.1-pro",
        contents=[video_part, prompt]
    )
    return response.text
```

- 小于 20MB 直接传；超过 20MB 使用 File API 上传
- 超长视频按集拆分，每集分别调用 Gemini

## 6. 部署方案

### 6.1 服务器部署（推荐）

```
服务器（Linux / Windows Server）
  └── uvicorn 运行 FastAPI
       ├── 托管前端静态文件
       ├── SSE 处理生成请求
       └── 调用 Gemini API
```

**启动方式**：

```bash
# 安装依赖
pip install -r requirements.txt

# 开发启动
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# 生产启动（推荐 systemd 或 supervisor 管理进程）
uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1
```

**说明**：
- `workers=1`：因为 LLM 调用是 IO 密集型，单 worker 利用 async 已足够；多 worker 反而会竞争 SQLite 写入
- 如果服务器有 nginx，可配置反代 + HTTPS；如果只是家人/朋友访问，直接 HTTP + 端口也可以
- 所有数据（数据库 + 文件）都在 `data/` 目录下，备份只需打包该目录

### 6.2 Docker 部署（可选）

提供 Dockerfile 供有容器化需求的场景使用，非必须。

## 7. 安全与隐私

- 视频文件生成完成后立即删除，不留存
- API Key 存储在服务端环境变量或 `.env` 文件中，不暴露给前端
- 前端调用 `/api/settings` 时，API Key 返回脱敏格式（`sk-****`）
- 无用户系统，无密码，通过 IP 或端口限制访问范围（如仅允许内网或特定 IP）
